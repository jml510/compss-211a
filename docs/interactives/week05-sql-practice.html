SQL interview practice

Fourteen SQL practice questions of the kind used in screening tests for data analyst jobs. These tests are common in private-sector hiring. The data is a sample of the San Francisco 311 requests from Week 5. Queries run in your browser and are not saved or sent anywhere.

Week 5 · Optional · 45–60 minutes · Needs an internet connection
The tables

requests

1,500 rows. One row is one request.

  • request_id: text
  • opened_at: date and time, such as 2026-08-03T13:00:05.000
  • status: Open or Closed
  • category: the kind of request
  • channel: how it came in. Can be missing. Includes 11 Test requests.
  • district: supervisor district number. Can be missing.
  • hours_to_close: missing if the request is not closed

districts

11 rows. One row is one supervisor district.

  • district: number from 1 to 11
  • supervisor: name as the city published it in 2022. One name is out of date.

districts_v2

A copy of districts with a mistake in it. Used in question 9.

days

7 rows. One row is one day of the sample week.

  • day: date, such as 2026-08-03
  • weekday: name of the day
  • is_weekend: 1 for Saturday and Sunday, otherwise 0

To see the first rows of a table, run SELECT * FROM requests LIMIT 5;

This page runs SQLite. PostgreSQL and MySQL write some functions differently, mostly date functions.

How to approach an interview question
  1. Say the question back in your own words, including what one row of the answer is.
  2. Look at the tables. Find the columns you need and the column that connects two tables.
  3. Build the query in small steps and run it after each step.
  4. Check missing values, repeated rows, and ties.
  5. Check the numbers. Does the total add up? Is a share between 0 and 1?

Interviewers pay attention to steps 4 and 5. Say your checks out loud.
