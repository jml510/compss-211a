0 / 13 complete
  1. Find out where you are. Run pwd. Question 1: where am I?
  2. List what is here. Run ls. Question 2: what is here?
  3. Step into data/ and confirm the move. Run cd data, then pwd. The prompt also changes, but check with pwd instead of relying on the prompt.
  4. Look at the start of sample.csv without opening it in an editor. Run head sample.csv. Look at a file before you change it.
  5. Go back to the project root, the top folder of the project. Run cd ... Two dots mean the parent directory, the folder one level up.
  6. Make a folder, step into it, and create an empty file. Run mkdir scratch, then cd scratch, then touch notes.txt, then ls. The tree shows where you are and the new file. Question 4: how will I check the result? Run ls.
  7. Go back up and copy a file into the new folder. Run cd .., then cp notes.md scratch/notes_copy.md, then ls scratch. The original notes.md stays where it was. cp keeps the original. mv, which you use later, does not.
  8. Run the summary script from the project root. Run python3 scripts/summarize_csv.py and watch summary.txt appear in the tree. Question 3: what exact path will this command read or change?
  9. Run it from the wrong folder. Run cd scripts, then python3 summarize_csv.py. Read the error, then answer below.

    This question unlocks after you hit the error in mission 9.

    Predict, then check: the same script worked from project/ a moment ago. Why did it fail from scripts/?

    Why the script failed from scripts/

    Python found and ran the script both times, because you gave a correct path to the script itself. The failure happened inside the script, at open("data/sample.csv"). A relative path starts from your current working directory, not from the folder that contains the script.

    from ~/project data/sample.csv → ~/project/data/sample.csv exists
    from ~/project/scripts data/sample.csv → ~/project/scripts/data/sample.csv missing

    Run project scripts from the project root. When you get a path error, first run pwd, then read the missing path in the error. Only then change the code. Try cd .. and run the script again.

  10. Move the summary into results/. From the root, run mv summary.txt results/, then ls results. Keep the / at the end. It tells mv that the destination must be a folder that already exists. Question 4: how will I check the result? Run ls results.
  11. Mistype the folder name. What does mv do when the destination folder is spelled wrong? Type python3 scripts/summarize_csv.py to create a new summary.txt, then mv summary.txt result, leaving out the s. Look at the tree, then answer below.

    This question unlocks after the mistyped mv in mission 11.

    mv printed nothing, and summary.txt is no longer in the tree. Where did it go?

    What mv does with its second argument

    mv looks at its second argument. If that path is an existing folder, the file moves inside it. If it is anything else, the file is renamed to that path. It never asks which one you meant, and it prints nothing when it succeeds.

    mv summary.txt results/ results/ is an existing folder → moved to results/summary.txt
    mv summary.txt result nothing named result exists → renamed to result
    mv summary.txt result/ nothing named result exists → refused: No such file or directory

    End a destination folder with /. Then a typo in the folder name gives an error instead of renaming your file. Also, if the destination is a file that already exists, mv and cp replace it without asking, and the old contents are gone. You can fix a misnamed file with another mv, but leave result where it is. The next mission removes it.

  12. Delete the stray file. Run pwd, then ls -l result to see the exact file you are about to remove, then rm result. Then answer below. Check the exact path first, then remove that same path.

    This question unlocks after rm removes a file in mission 12.

    rm result printed nothing. Where is the file now?

    Why to check before rm

    rm prints nothing when it succeeds. There is no Trash, no confirmation, and no undo. rm removes whatever path you give it, starting from the working directory. So work in this order: pwd to see where you are, ls on the exact path to see what will be removed, then rm on that same path. Do not rm a path you have not just listed.

    Two options make it more dangerous. -r removes a folder and everything inside it. -f hides the errors that would otherwise stop it. rm -rf with the wrong path can delete a whole project.

  13. Remove a whole folder, then bring the project back. Run rm results and read the error. Then run rm -r results and watch the folder and everything in it disappear from the tree. Finally, type reset. This practice terminal has reset. Your computer does not.

Remember

  • pwd, ls, and cd answer three questions: where am I, what is here, how do I get there.
  • A relative path starts from the working directory; an absolute path starts from the file-system root.
  • .. is the parent directory and ~ is your home directory. cd - returns to the previous one.
  • Tab completion helps you avoid typos. Use it often.
  • Run project scripts from the project root, so the relative paths inside them point to the right files.
  • mkdir, touch, and cp create; mv moves. Run ls on the destination afterwards to check. mkdir -p also creates missing parent folders and gives no error if the folder already exists.
  • End a destination folder with /. If the folder does not exist, mv refuses instead of renaming your file.
  • mv and cp replace an existing destination file without asking. Check the destination with ls first.
  • rm does not use the Trash. First pwd, then ls on the exact path, then rm on that path. -r takes a whole folder.
  • This practice terminal has reset. Your computer does not. On your own computer, practice on a copy you don't mind losing, and delete files through the Trash in Finder or Explorer.
