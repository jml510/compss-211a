Counting rows vs. counting recorded values

For all six requests:

  • COUNT(*) / len(requests): 6 rows.
  • COUNT(hours_to_close) / requests["hours_to_close"].count(): 4 recorded durations.

B’s zero counts as a recorded duration. C and F have no duration, so only the row count includes them.

How many rows will each left join return if district 2 has two labels? Predict, then check the box.

That’s all three. What to check in your own queries:

  • In SQL, WHERE x != 'value' drops the rows where x is missing. Pandas keeps them.
  • In pandas, groupby drops missing keys unless you add dropna=False. SQL keeps them as one group.
  • An inner join drops rows with no match. A left join keeps them, and a repeated key in the lookup table repeats rows.

Using this in the notebook

Compare request IDs and group counts to check which rows each query includes. Before joining a lookup table, check for duplicate keys.

In pandas, add validate="many_to_one" to merge() to reject duplicate lookup keys. In SQL, find them with:

SELECT district, COUNT(*) AS rows_per_key
FROM districts
GROUP BY district
HAVING COUNT(*) > 1;
